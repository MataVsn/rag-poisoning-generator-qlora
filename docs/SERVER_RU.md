# Запуск на арендованном сервере

Проект уже подготовлен локально. Сервер нужен для скачивания весов, CUDA-проверки и обучения. Разворачивать LangSmith/Langfuse/Phoenix заново для обучения не требуется: измерения обучения сохраняются в JSON, а генератор затем подключается к вашему RAG-эксперименту.

## Подключение и перенос

После создания инстанса на Vast.ai открыть Connect и скопировать SSH-команду. Нужны адрес, SSH-порт, пользователь и доступ зарегистрированным SSH-ключом. Приватный ключ и пароль в переписку не отправлять. Если ключ ещё не настроен, сначала настроить его, потом создавать машину.

На ноутбуке загрузить архив, подставив USER, HOST, PORT из SSH-команды:

```sh
scp -P PORT ./RAG_GenAI_Endterm.zip USER@HOST:/tmp/
ssh -p PORT USER@HOST
```

Это шаблон; реальные значения берутся из Connect. Папку проекта разместить на сохраняющемся диске инстанса, например в `/workspace`, если этот путь предусмотрен выбранным образом. Не предполагать, что `/tmp` сохраняется: там только временный архив.

На сервере, после перехода в выбранную папку:

```sh
unzip /tmp/RAG_GenAI_Endterm_v2.zip
cd rag-genai-endterm
sh scripts/bootstrap_gpu.sh
```

Требуются Python с venv, unzip, tmux. При их отсутствии установим зависимости средствами конкретного образа. Для Ubuntu/Debian с root-доступом типовая команда: `apt-get update && apt-get install -y python3-venv unzip tmux`. Не переустанавливать драйвер NVIDIA внутри контейнера; сначала изучить вывод `nvidia-smi` и preflight.

## Обучение, которое переживёт отключение SSH

```sh
sh scripts/remote_train.sh smoke
sh scripts/remote_train.sh status
sh scripts/remote_train.sh logs
```

`smoke` запускает проверки и 20 шагов обучения в tmux. `logs` показывает обновления; Ctrl+C останавливает просмотр, обучение продолжает работать. `status` показывает последние строки и статус выхода. `exit_code=0` означает успешное завершение команды; ненулевой код требует прочитать лог. Если сервер аварийно перезапустился, запись `running` может остаться устаревшей: проверять также наличие tmux-сессии.

После успешного smoke и проверки фактической памяти:

```sh
sh scripts/remote_train.sh train
```

Одновременно допускается одна сессия обучения. Подготовка окружения выполняется в обычном терминале; запуск smoke/train — в фоне. Скрипт не запускает обучение автоматически после неудачной проверки. Перезапуск сервера tmux не переживёт; полный запуск заново не является продолжением checkpoint. При обрыве процесса сохраним checkpoint и отдельно настроим возобновление перед следующим запуском.

Далее выполнить сравнение генерации из README_RU.md. Перед удалением инстанса:

```sh
.venv/bin/python scripts/export_results.py
```

На ноутбук скопировать показанный архив через scp. В нём адаптеры, результаты и логи, без промежуточных checkpoint и без базовых весов из Hugging Face cache. Для продолжения обучения после удаления сервера checkpoint нужно скопировать отдельно. Экспорт не выключает инстанс.

У Vast.ai остановленный инстанс сохраняет диск, но плата за хранение продолжается. Удаление инстанса уничтожает его локальные данные — сначала скачать и проверить результаты. Источник: https://github.com/vast-ai/docs/blob/main/guides/instances/manage-instances.mdx

## Что проверено

Данные, токенизация и локальные тесты проверены. Для новых серверных команд проверен синтаксис; detached-запуск tmux и GPU-проход будут проверены после появления инстанса. До этого время обучения, расход памяти и совместимость конкретного хоста не считаются измеренными.
