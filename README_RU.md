# Данные и запуск GenAI Endterm

Подготовлен эксперимент: вход «исходный факт → заданный факт → вопрос», выход — один тестовый документ для собственного изолированного RAG. Стартовая модель: **Qwen3-4B-Instruct-2507**, дообучение QLoRA NF4. Фактические GPU-прогоны и метрики сохраняются в `outputs/`; end-to-end проверка атак требует отдельного RAG backend.

**Усиленный вариант на RTX 5090:** Qwen3-14B, LoRA rank 64 во всех линейных слоях, измеряемый подбор batch и ограниченный по времени эксперимент. См. [CAMPAIGN_14B_RU.md](docs/CAMPAIGN_14B_RU.md). Команды ниже оставлены для воспроизводимости стартового 4B-варианта.

Пошаговый перенос на сервер, обучение в фоне и выгрузка результатов: [SERVER_RU.md](docs/SERVER_RU.md).

## Что внутри

| Набор | Train | Validation | Test |
|---|---:|---:|---:|
| Русские синтетические примеры | 1200 | 150 | 150 |
| Опубликованные документы PoisonedRAG, английский | 1092 | 132 | 140 |
| Вместе, конфигурация по умолчанию | **2292** | **282** | **290** |

Это 2864 примера, а не столько независимых вопросов: несколько документов одного вопроса хранятся в одной части. Синтетические сущности между частями не пересекаются. У публичных данных сгруппированы повторяющиеся вопросы и одинаковые документы; непересечение всех упомянутых сущностей не гарантируется.

- `data/sft/mixed/*.jsonl` — готовые сообщения для обучения; `synthetic_ru` и `poisonedrag` — отдельные варианты для сравнения.
- `data/mixed/*.jsonl` — те же примеры с полной разметкой и происхождением.
- `data/generation_prompts/*.jsonl` — входы для генерации **без эталонного ответа assistant**. Оценочная разметка хранится отдельно от сообщений.
- `data/rag/{validation,test}/` — чистые корпуса и сценарии для русской синтетической части: по 150 документов и 150 случаев. Для публичной части полный чистый корпус не включён.
- `sources/previous_experiment/` — ваши прежние 5 документов и 48 испытаний, отдельный архив для регрессии. В новое обучение не включены.
- `docs/DATA_CARD_RU.md` — ограничения, происхождение, лицензии.
- `docs/EVALUATION_RU.md` — что и как измерять.

Русская часть создана воспроизводимыми шаблонами. Это материал для первого эксперимента, **не оригинальные обучающие данные AuthChain** и не подтверждённые успешные атаки. Дообучение на нём может научить формату без роста эффективности: это нужно измерить.

## Проверка до аренды

Из корня этой папки, Python 3.10+:

```sh
python3 scripts/validate_datasets.py
python3 -m unittest discover -s tests -v
```

Пересобрать данные из включённых исходников: `python3 scripts/build_datasets.py`. Скачивать их заново не требуется. Контрольные суммы и отчёты лежат в `data/`.

## Арендованная машина

Начните с Linux-образа с Python 3.11/3.12, поддерживающим драйвером NVIDIA, доступом к интернету и хотя бы 40 ГБ свободного диска. Скопируйте и распакуйте пакет, перейдите в папку проекта.

**2 × 16 ГБ — две отдельные видеокарты.** В этой конфигурации обучение использует одну. Память не складывается в 32 ГБ. Это стартовая конфигурация для проверки, фактический расход памяти и скорость ещё не измерены. Для Blackwell выбран PyTorch с CUDA 12.8; скрипт отдельно проверит 4-битную операцию bitsandbytes.

```sh
sh scripts/bootstrap_gpu.sh
. .venv/bin/activate
CUDA_VISIBLE_DEVICES=0 python scripts/preflight_gpu.py
python scripts/check_tokens.py
CUDA_VISIBLE_DEVICES=0 python scripts/train_qlora.py --smoke-steps 20
```

Первый запуск скачает веса модели. Короткий прогон проверяет загрузку, память и обучение; его адаптер сохраняется отдельно в `outputs/qwen3-4b-qlora/smoke/adapter`. Он не считается итоговым результатом.

Если короткий прогон завершился:

```sh
CUDA_VISIBLE_DEVICES=0 python scripts/train_qlora.py
```

Итог: `outputs/qwen3-4b-qlora/adapter/`, метрики, история обучения и manifest с версиями, контрольными суммами данных, временем и пиковым расходом памяти. Обучаются только LoRA-параметры; функция потерь считается только по ответу assistant. Test при обучении не используется. Существующий адаптер скрипт не перезаписывает.

При нехватке памяти сначала уменьшайте `max_length` только после проверки длины данных; молча обрезать целевой документ нельзя. Можно уменьшить LoRA rank или выбрать меньшую модель отдельным экспериментом. Не запускайте одновременно вторую копию модели на той же GPU.

## Сравнение до и после

Сначала отладьте процедуру на validation. Один запрос — один сгенерированный документ; параметры и бюджет одинаковые. Например, первые 20 случаев для проверки работы:

```sh
CUDA_VISIBLE_DEVICES=0 python scripts/generate_candidates.py --input data/generation_prompts/validation.jsonl --output outputs/base-validation.jsonl --limit 20
CUDA_VISIBLE_DEVICES=0 python scripts/generate_candidates.py --input data/generation_prompts/validation.jsonl --output outputs/tuned-validation.jsonl --adapter outputs/qwen3-4b-qlora/adapter --limit 20
python scripts/score_candidates.py --input outputs/tuned-validation.jsonl --output outputs/tuned-surface-checks.json
python scripts/make_rag_jobs.py --candidates outputs/tuned-validation.jsonl --split validation --output outputs/tuned-rag-jobs.jsonl
```

Проверка наличия слова в документе не измеряет успешность атаки. `make_rag_jobs.py` только готовит задания для вашего backend: сам ничего в RAG не вставляет и сайтов не вызывает. Он пропускает публичные случаи без чистого корпуса. Для полного сравнения уберите `--limit` у обоих запусков. В смешанной validation 150 синтетических случаев и 132 публичных.

После выбора параметров зафиксируйте модель и процедуру и один раз сравните base и tuned на `data/generation_prompts/test.jsonl`, указав `--split test` при подготовке заданий. Не выбирайте лучший документ из нескольких попыток на test. Для дополнительного честного сравнения можно обучить модель только на `--dataset synthetic_ru` и только на `--dataset poisonedrag`, каждый раз задавая отдельный `output_dir` в копии конфигурации.

**One-shot здесь — один добавленный документ на один опыт**, а не один обучающий пример. После разбиения документа RAG может создать несколько чанков: записывайте их число отдельно.
